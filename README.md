# marloa-terraform-module

Reusable Terraform modules for Marloa's AWS infrastructure. Environments are
composed from these modules in
[`marloa-terraform`](https://github.com/marloa-ai/marloa-terraform).

| Module | Purpose |
| ------ | ------- |
| [`alb`](modules/alb) | Internal ALB reachable only from CloudFront VPC origins |
| [`cloudfront-app`](modules/cloudfront-app) | CloudFront: SPA from private S3 + `/api/*` to the ALB, WAF, security headers |
| [`ecr`](modules/ecr) | Immutable, scanned ECR repos with cross-account pull |
| [`ecs-service`](modules/ecs-service) | Fargate ARM64 service, ALB target, autoscaling, IAM, logs |
| [`github-oidc`](modules/github-oidc) | GitHub OIDC provider + plan/apply/deploy/ECR-push roles |
| [`kms`](modules/kms) | Environment CMK usable by RDS, Secrets Manager, Logs, SNS |
| [`observability`](modules/observability) | SNS alarm topic + baseline RDS/ALB/ECS alarms |
| [`rds-postgres`](modules/rds-postgres) | PostgreSQL with a `DATABASE_URL` secret; password never in state |
| [`terraform-state`](modules/terraform-state) | KMS-encrypted, versioned state bucket (S3-native locking) |
| [`vpc`](modules/vpc) | 2-AZ VPC, NAT, S3 endpoint, optional interface endpoints, flow logs |
| [`waf-cloudfront`](modules/waf-cloudfront) | CloudFront-scope WAF: rate limit + AWS managed rules |

## Using a module

Reference a released tag — never a branch or an unpinned ref:

```hcl
module "vpc" {
  source = "git::ssh://git@github.com/marloa-ai/marloa-terraform-module.git//modules/vpc?ref=vpc-v0.1.0"
  # ...
}
```

Each module is versioned on its own. Tags look like `<module>-vX.Y.Z`
(`vpc-v0.1.0`, `rds-postgres-v0.2.1`).

## Releasing

1. Open a PR. Its **title** must be a Conventional Commit, scoped to the
   module: `feat(vpc): add IPv6`, `fix(ecs-service): ...`,
   `feat(rds-postgres)!: ...` for breaking changes.
2. CI runs fmt, validate (every module), tflint, trivy (fails on
   HIGH/CRITICAL), checks that READMEs are regenerated, and prints a release
   preview.
3. Squash-merge. The `Release modules` workflow tags every module that changed
   since its last tag: `BREAKING CHANGE`/`!` → major, `feat` → minor,
   anything else → patch.
4. Bump the `?ref=` in `marloa-terraform` in a separate PR and review the plan.

To test an unreleased change, point a `marloa-terraform` branch at
`?ref=<commit-sha>` and attach its plan to the module PR. Do not merge
`marloa-terraform` with a non-tag ref.

## Conventions

- Files per module: `versions.tf`, `variables.tf`, `main.tf`, `outputs.tf`,
  `README.md` (inputs/outputs generated by terraform-docs).
- Every variable and output has a description; inputs are validated where a
  bad value would otherwise fail late at apply time.
- Modules declare minimum provider versions (`>= 6.0`); root stacks pin exact
  ranges and commit lock files.
- No provider blocks inside modules. Modules that need another region take an
  aliased provider (e.g. `waf-cloudfront` with `aws.us_east_1`).
- No tags variable: callers set `default_tags` on the provider.
- Security findings that are intentional carry an inline
  `#trivy:ignore:<ID>` with the reason on the line above.

## Local checks

```bash
pre-commit install          # fmt, validate, tflint, terraform-docs, trivy on commit
pre-commit run --all-files
```

Tool versions: Terraform `1.16.4` (`.terraform-version`), tflint `0.64.0`,
terraform-docs `0.24.0`.
